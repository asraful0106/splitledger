# Conventions

Decisions locked in Phase 0. Update this file when a convention changes.

## Casing

- **TypeScript**: `camelCase` for variables, functions, and object keys.
- **SQL / JSON over the wire**: `snake_case`.
- Conversion happens at the **repository boundary** only. Services and controllers work with
  camelCase objects; repositories map to/from `snake_case` columns.

## Money

- Stored and computed as an **integer count of paisa**. Never floats.
- TypeScript uses `bigint` for amounts (matches Postgres `BIGINT` and avoids precision loss).
- **Over the wire**, an amount is a **string of minor units** (e.g. `balanceMinor: "0"`) — JSON
  can't carry `bigint`, and a number would risk precision. Parse with `BigInt(value)` at the edge.
- **Currencies**: a curated list of 2-decimal currencies (`shared/money/currencies.ts`). Every
  supported currency uses 100 minor units per major unit, so the paisa/minor model is unchanged.
  Each account carries one currency; amounts inherit it.
- **Never sum across currencies.** Totals are grouped per currency (Home shows one total per
  currency, insights returns one bucket per currency). There is no FX conversion anywhere.
- An account's **currency is locked once it has a transaction** (400 `currency_locked`); before that
  it can be changed.
- Percentages are **basis points**: integer, `10000` = 100%.
- Splitting uses `shared`'s `split()` — the single source of truth. The client may preview with
  it, but the server result is authoritative.
- Formatting goes through one helper: `formatMoney(minor, currency)` in `shared`. No ad-hoc math.
- An account's **active parts must sum to exactly 10000 bp**: enforced in the service and
  re-verified inside the DB transaction before commit.
- Removed parts are **soft-archived** (`archived_at`), never deleted, so historical entries keep a
  valid reference.

## Ledger

- **Append-only.** Transactions and entries are never updated or deleted. A correction is a new
  **reversal** transaction whose `reverses_transaction_id` points at the original; a transaction can
  be reversed at most once (unique partial index).
- **Sign convention.** Entry amounts are signed: `+` on a deposit, `−` on a withdrawal. A reversal
  is a transaction of the **opposite type** with negated entries.
- **Invariant.** `SUM(entries) = +amount` for a deposit and `−amount` for a withdrawal. Enforced by
  a deferred constraint trigger, so a commit with unbalanced entries fails.
- **Concurrency.** Every money write runs in one DB transaction that locks the account (and the
  affected parts) `FOR UPDATE` first, so writes to an account serialize.
- **Idempotency.** `POST /deposits` and `POST /withdrawals` accept an optional `Idempotency-Key`
  header; a repeat returns the original transaction (unique `(user_id, idempotency_key)`).
- **Overdraw.** A withdrawal (or a reversal that would) never takes a part below zero — it is
  rejected with `insufficient_balance`, never clamped.
- **Audit.** `transaction_created` and `transaction_reversed` are recorded in `audit_log`.

## Styling

- **Tailwind CSS v4** via `@tailwindcss/vite`, plus CSS custom properties for design tokens
  (`apps/web/src/index.css`).
- Mobile-first. Follow the design skills referenced in `.clude/CLAUDE.md` §8.

### Motion

- Tokens: `--ease-out`, `--ease-in-out`, `--ease-drawer`, `--dur-fast`, `--dur-base`.
- Animate **`transform` and `opacity` only** (`clip-path` is the sanctioned third). Never animate
  layout properties, and never `transition: all`.
- Press feedback is `scale(0.97)` on `:active`; hover styles live behind
  `@media (hover: hover) and (pointer: fine)`.
- Every animation has a `prefers-reduced-motion: reduce` variant (opacity cross-fade, no motion),
  and `prefers-reduced-transparency` / `prefers-contrast` are honoured.
- JS-driven gestures write to `element.style.transform` directly — never React state per frame.

### Bottom sheets

- One hand-rolled `components/Sheet.tsx`: portal, scrim, drag-to-dismiss (distance **or** velocity
  past a small hysteresis), focus trap, Escape, body scroll lock, safe-area padding.
- Sheet content is a scrolling field area (`.sheet-scroll`) plus a **pinned action row**
  (`.sheet-actions`), so the primary button is always reachable.

### PWA

- `vite-plugin-pwa` emits `manifest.webmanifest` + a service worker that precaches the app shell.
- **API responses are never cached** (`navigateFallbackDenylist: [/^\/api\//]`, no runtime caching) —
  money data must never be served stale.
- Icons are generated by `apps/web/scripts/generate-icons.mjs` (dependency-free PNG encoder); run
  `pnpm --filter web icons` (also runs on `prebuild`).
- Updates use `registerType: "prompt"`; `UpdatePrompt` offers a reload when a new worker is waiting.

## Time & periods

- Timestamps are stored as `timestamptz` (UTC) and **grouped/displayed in Asia/Dhaka**.
- Period boundaries are built in `shared/insights/periods.ts` with an explicit `+06:00` offset
  (Bangladesh has no DST). `from` is inclusive, `to` is exclusive.
- The **fiscal year is July–June** (Bangladesh): `fiscalYearRange(2026)` spans
  `2026-07-01T00:00:00+06:00` → `2027-07-01T00:00:00+06:00`, labelled `2026–27`.
- The insights API takes an explicit `from`/`to` range; the client offers month / last-month /
  fiscal-year / custom presets.

## CSV export

- One row per ledger entry, RFC-4180 quoting, UTF-8 BOM (so Excel detects the encoding), `\n` line
  endings, timestamps in Dhaka with `+06:00`.
- Amounts appear twice: signed major (`-12.34`) and `amount_minor` (integer paisa).
- Export is read-only and scoped to the authenticated user; the filename uses the inclusive Dhaka
  dates.

## API

- REST, JSON, prefix `/api/v1`. Resource-oriented plural nouns.
- Success: `{ data }`. Failure: `{ error: { code, message, details? } }`.
- Layering: `routes → controllers → services → repositories`. Business logic in services,
  SQL only in repositories.

## General

- Conventional commits (`feat:`, `fix:`, `chore:`).
- No `any`, no `console.log` (use `pino`), no commented-out code.
- Prefer boring, explicit code — especially around money.
